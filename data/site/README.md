## What a fixture export needs beyond the plan

Every seed record that the resume snapshot reads carries a `Public_Key__c`, and exactly one current role (Seed Platform Architect) is ticked `Is_Primary_Role__c`. The resume page also shows a credential verification link, which comes from a `Portfolio_Config__mdt` record. A tree import cannot load custom metadata, so `Portfolio_Config.apex` in this folder creates one after the import. The link it sets is an example address.

The certification names are real Salesforce credential names and Salesforce is the issuer account. Every employer, role, highlight and summary is invented.

## Load it

Into a scratch org only. Never into production.

```
sf data import tree --plan data/site/plan.json --target-org <scratch-alias> --json
sf apex run --file data/site/Portfolio_Config.apex --target-org <scratch-alias> --json
```

The running user needs field access to the custom fields first. In a fresh scratch org assign `Portfolio_Admin` to the admin before the import.

`Lock_Sort_Across_Personas__c` defaults to true, and the `Sync_Experience_Highlight_Sort_Orders` flow then copies one sort value into every persona order. The highlights here set it to false so each persona keeps its own order.

## Refresh the site fixtures

`web/fixtures` is a clean export of this seed and nothing else. Seed a scratch org with `scripts/scratch-ready.js` (it imports this plan, the other plans under `data/` and the docs cache), run `Portfolio_Config.apex`, assign `Portfolio_Site_Build` to the admin, then from `web` run `SF_TARGET_ORG=<alias> node build/build.mjs --export --write-fixtures`. After it, run `node tailor-eval/build-snapshot.mjs` to rebuild the tailoring snapshot, and restore `web/fixtures/recorded` with `git checkout -- web/fixtures/recorded`, because the export removes that folder. Never commit `web/.data`.

The export reads no source file text, so `SourceController.getSourceFiles` comes back empty in the fixtures. `scripts/scratch-ready.js` caches the docs and not the component source files.

## Layout

One folder per area. Later rounds add sibling folders (for example `data/delivery/` or `data/pillars/`) with their own plan, and never edit this one.
